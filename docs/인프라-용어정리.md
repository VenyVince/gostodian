# 인프라·보안 용어 정리

`gostodian` 같은 **점검 머신 → SSH → 홈랩/서버** 구조를 읽을 때 자주 나오는 말을,  
왔다 갔다 하지 않아도 한눈에 이어지도록 풀어 쓴 메모다.

한 줄로 먼저 잡으면 이렇다:

> **OCI VM** 위에 **VPN**으로만 들어가고, **SSH 키**로 명령을 보내고,  
> **컨트롤러**가 **허용된 동사만** 실행하게 막으며,  
> **Podman/systemd**로 서비스를 돌리고, **메트릭**으로 상태를 본다.

---

## 1. 큰 그림: 어디에 무엇이 있나

### OCI VM

Oracle Cloud Infrastructure에서 빌린 **가상 서버**다.  
물리 서버를 직접 두지 않고, 클라우드에 “컴퓨터 한 대”를 빌려 쓰는 것이다.  
홈랩의 컨트롤러·점검 대상·VPN 엔드포인트 같은 역할이 이 VM 위에 올라갈 수 있다.

### OCI Bastion / VPN이 가지고 있는 의미

- **Bastion(배스천)**: 바깥에서 내부 서버로 바로 들어가지 못하게 하고,  
  **중간 관문 서버** 하나만 공개해 두고 거기를 통해서만 들어가게 하는 패턴이다.  
  “앞문만 열어 두고, 안쪽 방은 앞문을 통과한 사람만” 구조다.
- **VPN**: 내 PC(또는 점검 머신)와 OCI 쪽 네트워크를 **암호화된 터널**로 이어서,  
  마치 같은 사설망에 있는 것처럼 보이게 만든다.

둘 다 하는 일은 같다: **인터넷에 SSH(22)를 대놓고 열어두지 않고**,  
신뢰할 수 있는 경로(배스천 또는 VPN)로만 관리 접근을 허용한다.

### OCI Security List / 퍼블릭 22번 차단

- **Security List**: OCI의 **방화벽 규칙 목록**이다.  
  “이 VCN/서브넷으로 어떤 IP·포트 트래픽을 허용할지”를 정한다.
- **퍼블릭 22번 차단**: 인터넷(`0.0.0.0/0`)에서 SSH 포트(22)로 들어오는 연결을 **막는다**는 뜻이다.  
  즉 “누구나 인터넷에서 `ssh user@공인IP` 하면 된다” 상태를 없앤다.  
  SSH는 **VPN IP 대역에서만**, 또는 Bastion을 통해서만 오게 두는 식으로 좁힌다.

### peer

VPN·네트워크에서 **맞은편 상대**를 가리킨다.  
예: WireGuard에서 “이 터널의 peer = 상대방 공개키 + 허용 IP”처럼,  
연결의 한쪽 끝점(엔드포인트)을 peer라고 부른다.  
“나와 직접 짝을 이루는 상대”라고 보면 된다.

## 2. SSH와 키: 어떻게 들어가는가

### SSH

**Secure Shell**. 원격 서버에 암호화된 채널로 접속해 **셸/명령을 실행**하는 프로토콜·도구다.  
비밀번호 대신 **키 쌍**으로 인증하는 경우가 많다.

### sshd

서버 쪽에서 돌아가는 **SSH 데몬(서버 프로세스)**이다.  
클라이언트의 `ssh` 연결을 받아 인증하고, 세션·명령을 처리한다.  
설정은 보통 `/etc/ssh/sshd_config`에 있다.

### SSH 키 운용 방식

키는 보통 **한 쌍**이다.

| 이름 | 역할 | 어디에 두나 |
|------|------|-------------|
| **개인키(private key)** | 내가 “나”임을 증명 | 점검 머신 `secrets/id_ed25519` 등. **절대 유출 금지** |
| **공개키(public key / pub키)** | 서버가 그 증명을 검증 | 서버 `~/.ssh/authorized_keys` |

운용 원칙은 대략 이렇다:

1. 개인키는 점검 머신(또는 컨트롤러)에만 둔다.
2. 공개키만 서버에 등록한다.
3. 가능하면 **한 용도·한 키**(예: gostodian 전용 키)로 분리한다.
4. 키에 **제한 옵션**(아래 `restrict`, `command=`, `from=`)을 붙여 폭발 반경을 줄인다.
5. 권한·호스트 키 검증(`known_hosts`)을 끈 채로 쓰지 않는다.

### pub키

**공개키**의 줄임말이다.  
`ssh-ed25519 AAAA...`처럼 생긴 한 줄이 서버에 등록되는 쪽이다.  
공개키만으로는 로그인할 수 없고, 짝이 되는 개인키가 있어야 한다.

### authorized_keys

서버의 `~/.ssh/authorized_keys` 파일이다.  
“이 공개키를 가진 사람은 이 계정으로 SSH 올 수 있다”는 **허용 목록**이다.  
여기에 `restrict`, `from=`, `command=` 같은 **옵션을 키 앞에 붙여** 권한을 더 조일 수 있다.

### passphrase

개인키 파일을 한 번 더 잠그는 **암호문**이다.  
개인키 파일이 유출돼도 passphrase를 모르면 바로 쓰기 어렵다.  
자동화(무인 점검)에서는 passphrase 없는 키를 쓰거나,  
에이전트/시크릿 스토어로 풀어서 쓰는 식으로 설계를 나눈다.

### 권한 0600 의미

유닉스 파일 모드다.

- `0` = 특수 비트 없음  
- `6` = 소유자 읽기+쓰기 (`rw-`)  
- `0` = 그룹 권한 없음  
- `0` = 기타 사용자 권한 없음  

즉 **소유자만 읽고 쓸 수 있다**.  
SSH는 개인키·`authorized_keys`가 다른 사용자에게 열려 있으면  
보안상 위험하다고 보고 **접속을 거부**하는 경우가 많다.  
그래서 `chmod 600 secrets/id_ed25519`를 강조한다.

### CA 방식 / TrustedUserCAKeys / New.PublicKey

일반 방식은 “서버마다 공개키를 `authorized_keys`에 등록”이다.  
**CA(Certificate Authority) 방식**은 다르다:

1. 조직이 **SSH CA**를 하나 둔다.
2. 사용자/호스트 공개키에 CA가 **짧은 수명의 인증서**를 발급한다.
3. 서버는 개별 공개키 목록 대신 **CA 공개키만 신뢰**한다.

- **TrustedUserCAKeys**: sshd 설정.  
  “이 CA가 서명한 사용자 인증서를 믿어라”라고 가리키는 파일 경로다.
- **New.PublicKey** (또는 비슷한 이벤트/필드명):  
  인증·감사 로그나 에이전트 API에서 **이번에 제시된 공개키**를 가리키는 식으로 쓰인다.  
  “새 키/제시된 키”를 검사·기록할 때 나오는 용어로 이해하면 된다.

CA 방식의 이점: 사람마다 서버에 키를 복붙하지 않아도 되고,  
인증서 **만료·폐기**로 접근을 회수하기 쉽다.

### from="VPN IP"

`authorized_keys` 옵션이다.  
예: `from="10.8.0.2"` → **그 IP(또는 대역)에서 온 연결만** 이 키로 인증을 허용한다.  
키가 유출돼도, 공격자가 VPN 밖(인터넷)에서 쓰면 막힌다.  
VPN을 전제로 한 “키 + 네트워크 위치” 이중 잠금이다.

### MITM

**Man-In-The-Middle(중간자 공격)**.  
통신 중간에 끼어들어 내용을 엿보거나 변조하는 공격이다.  
SSH에서는 처음 접속 시 서버 호스트 키를 `known_hosts`에 고정해 두고,  
이후 키가 바뀌면 경고를 내는 식으로 MITM을 막는다.  
`StrictHostKeyChecking`을 끄거나 `InsecureIgnoreHostKey`를 쓰는 것은 이 방어를 버리는 일이다.

### PTY

**Pseudo-TTY**. 대화형 터미널처럼 보이게 만드는 가상 터미널이다.  
`ssh`로 들어가서 셸을 쓰면 보통 PTY가 할당된다.  
자동화·강제 명령(forced command)에서는  
**PTY를 안 주고**(또는 `restrict`로 막아서) 대화형 남용을 줄이기도 한다.

### 포워딩

SSH의 **터널 기능**이다.

- 로컬/원격 포트 포워딩: 내 PC 포트 ↔ 원격 포트
- 에이전트 포워딩: 내 SSH 에이전트를 원격에 빌려줌
- X11 포워딩: GUI 전달

편하지만, 키가 탈취된 뒤 포워딩까지 열려 있으면 피해가 커진다.  
그래서 `restrict`는 포워딩·PTY·에이전트 등을 **한꺼번에 막는** 쪽에 가깝다.

### SSH ORIGINAL COMMAND

클라이언트가 SSH로 **실행하려 한 원래 명령 문자열**이다.  
서버 환경변수로는 보통 `SSH_ORIGINAL_COMMAND`로 보인다.  
`command="게이트스크립트"`로 forced command를 걸어 두면,  
사용자는 임의의 셸 대신 게이트만 실행되고,  
게이트는 `SSH_ORIGINAL_COMMAND`를 읽어 **허용 목록과 비교한 뒤** 실행 여부를 결정한다.

### forced command 게이트 / 허용 동사만 실행·통과?

- **forced command**: `authorized_keys`의 `command="..."` 옵션.  
  이 키로 로그인하면 **지정한 프로그램만** 실행되고, 일반 셸은 못 연다.
- **게이트**: 그 프로그램이 “문지기” 역할을 한다.  
  예: `/usr/local/bin/gostodian-gate`

흐름:

1. 점검 머신: `ssh host -- status` 같은 요청
2. 서버: 셸 대신 `gostodian-gate` 실행
3. 게이트: `SSH_ORIGINAL_COMMAND`가 화이트리스트(허용 동사)에 있는지 검사
4. 있으면 그 동사에 매핑된 안전한 동작만 수행, 없으면 거부

**허용 동사만 실행/통과** = “자유 셸이 아니라 `status`, `collect`, `reboot`처럼  
미리 정한 동사(명령 이름)만 통과시킨다”는 뜻이다.  
문자열을 그대로 셸에 넣지 않고, 테이블로 고정하는 것이 핵심이다.

### restrict,from="10.8.0.2",command="...", ssh-ed25519 AAAA... gostodian 의미

한 줄짜리 `authorized_keys` 항목을 앞에서부터 읽으면:

| 조각 | 의미 |
|------|------|
| `restrict` | 포워딩·PTY·에이전트 등 위험한 기능을 넓게 제한 |
| `from="10.8.0.2"` | 이 소스 IP에서만 이 키 허용 |
| `command="/usr/local/bin/gostodian-gate"` | 로그인 시 게이트만 실행 |
| `ssh-ed25519 AAAA...` | 키 종류 + 공개키 본문 |
| `gostodian` | 사람이 읽기 위한 **코멘트(라벨)**. 보통 키 용도/소유 표시 |

즉 “gostodian용 키는 VPN의 `10.8.0.2`에서만, 게이트를 통해서만, 제한된 기능으로”다.

### SSH push / SSH over VPN / “명령”이 뭐냐

- **SSH over VPN**: VPN 터널이 먼저 올라간 뒤, 그 **사설 IP로 SSH** 한다는 뜻이다.  
  공인 인터넷에 22를 열지 않아도 된다.
- **SSH push**: 컨트롤러(점검 머신)가 대상 서버로 **SSH로 접속해 작업/설정을 밀어 넣는** 방식이다.  
  반대로 대상이 컨트롤러를 주기적으로  Dual는 것은 보통 **풀(pull)/폴링**에 가깝다.
- 여기서 말하는 **명령**: SSH 세션 안에서 실행하는 원격 작업  
  (`dnf update`, 서비스 재시작, 로그 수집 스크립트, 게이트 동사 등)을 가리킨다.

### Go 바이너리

Go 언어로 컴파일해 만든 **실행 파일**이다.  
게이트·에이전트·컨트롤러를 단일 바이너리로 배포하기 쉽다.  
의존성 설치가 적은 편이라 서버에 올려 `gostodian-gate`처럼 쓰기 좋다.

## 3. 컨테이너·권한·패키지

### Podman

Docker와 비슷하게 컨테이너를 돌리는 도구다.  
대체로 **데몬리스·루트리스**에 더 친화적이고,  
RHEL/Fedora 계열에서 systemd와 잘 붙는 편이다.  
`gostodian` README는 Docker Compose를 쓰지만,  
홈랩 서버 쪽 런타임 논의에서는 Podman/Quadlet이 자주 나온다.

### Docker 권한이 root와 같다는 뜻

Docker(또는 소켓에 접근 가능한 사용자)는 보통 이런 일을 할 수 있다:

```bash
docker run -v /:/host ...
```

호스트의 루트 파일시스템을 컨테이너에 붙이면,  
컨테이너 안에서 호스트 파일을 root처럼 읽고 쓸 수 있다.  
그래서 “docker 그룹에 들어가 있다 ≈ **사실상 root**”라고 말한다.  
컨테이너 탈출/소켓 탈취 = 호스트 장악으로 이어질 수 있다.

### docker run -v /:/host

`-v /:/host`는 호스트의 `/`를 컨테이너의 `/host`에 **마운트**한다.  
점검·복구용으로 쓰이기도 하지만, 권한이 과도하면 치명적이다.  
바인드 마운트는 “격리”를 상당 부분 뚫는 스위치라고 보면 된다.

### distroless

거의 **배포판(셸, 패키지 관리자, 불필요 도구)을 뺀** 컨테이너 이미지다.  
앱 바이너리(+필수 런타임/CA 인증서 등)만 남겨 공격면과 이미지 크기를 줄인다.  
디버깅은 어려워지지만, 프로덕션 이미지 보안에는 유리하다.

### dnf와 apt

둘 다 **패키지 관리자**다.

| | 주로 쓰는 배포판 | 예 |
|--|------------------|----|
| **dnf** | Fedora, RHEL, Rocky, Alma | `dnf update` |
| **apt** | Debian, Ubuntu | `apt update && apt upgrade` |

홈랩이 Fedora/RHEL 계열이면 점검 문서에 `dnf`가, Ubuntu면 `apt`가 나온다.  
하는 일(설치·갱신·제거)은 같고 명령 체계만 다르다.

### sudoers

`/etc/sudoers`(및 `sudoers.d/`) 설정이다.  
“어느 사용자가 **어떤 명령을 root(또는 다른 유저)로** 실행할 수 있는지”를 정한다.  
자동화 계정에는 `ALL` 대신 **필요한 명령만** 허용하는 편이 안전하다.

### 와일드카드

`*`, `?`처럼 **여러 값을 한꺼번에 매칭**하는 패턴이다.  
sudoers·방화벽·파일 glob·명령 허용 목록에서 쓰인다.  
편하지만 너무 넓으면(`*`) 의도치 않은 명령까지 허용할 수 있어,  
화이트리스트에서는 가능한 한 구체적으로 쓰는 게 좋다.

## 4. 컨트롤러·자동화·구성 관리

### 컨트롤러 / 컨트롤러 로컬

- **컨트롤러**: 여러 서버를 **중앙에서 지휘**하는 쪽이다.  
  점검 스케줄, SSH push, 상태 수집, DAG 실행 같은 두뇌 역할.
- **컨트롤러 로컬**: 그 로직/상태/설정이 **컨트롤러 머신 안**에 있다는 뜻이다.  
  예: 작업 큐, 인벤토리, 이전 실행 결과 캐시가 컨트롤러 디스크에 있음.  
  “원격 서버에 에이전트가 상주”하는 모델과 대비해서 말하기도 한다.

### Ansible

서버 구성을 **코드(플레이북)**로 맞춰 주는 자동화 도구다.  
SSH로 접속해 패키지 설치, 파일 배치, 서비스 기동 등을 선언적으로 수행한다.  
“원하는 상태(desired state)”를 적어 두고, 실제 상태가 다르면 맞춘다.

### DAG

**Directed Acyclic Graph(방향성 비순환 그래프)**.  
작업들을 화살표로 이은 그래프인데, **사이클(무한 루프)이 없다**.  
예: `서비스 정지 → 업데이트 → 재부팅 → 서비스 기동 → 로그 수집`  
앞 단계가 끝나야 다음이 가는 **의존 관계**를 표현한다.

### 위상정렬

DAG에서 의존성을 깨지 않도록 **실행 순서를 일렬로 나열**하는 것이다.  
“A가 B보다 먼저” 같은 간선들을 만족하는 순서를 찾는다.  
점검 파이프라인에서 단계 순서를 정할 때 쓰는 개념이다.

### 드리프트가 생긴다

**Drift** = 의도한 설정/상태와 **실제 상태가 어긋남**이다.  
“변화가 생겼다”는 말에 가깝지만, 아무 변화가 아니라  
**선언해 둔 원하는 상태에서 벗어났다**는 뉘앙스가 강하다.

예:

- Ansible이 설치한 패키지 버전이 수동으로 바뀜
- 컨테이너 이미지 태그가 문서와 다름
- 방화벽 규칙이 플레이북과 불일치

그래서 “드리프트 감지”는 단순 변경 알림이 아니라  
**원하는 상태 대비 차이 검출**에 가깝다.

### 주기를 명시하는 문서

보통 다음에 해당한다:

- **런북(runbook)** / **점검 절차서**: “매주 일요일 03:00에 점검”처럼 **언제·무엇을** 적음
- **SLA/SLO 문서**: 수집·알림·복구의 주기·기한
- 프로젝트에서는 `config.yaml`의 스케줄 필드나  
  systemd timer / cron 설명이 “주기를 명시하는 문서/설정” 역할을 한다

즉 “주기”는 코드 한줄일 수도 있고, 운영 문서일 수도 있다.  
대화에서 “문서”라고 하면 **스케줄·주기가 적힌 운영/설정 문서**를 가리키는 경우가 많다.

### 플러그인 옵션

도구(SSH, Ansible, 모니터링 에이전트, CI 액션 등)에  
**기본 동작 외에 붙이는 설정 스위치**다.  
켜고 끄는 기능 플래그, 경로, 타임아웃, 허용 목록 같은 것이 옵션이다.

### 서브커맨드

하나의 CLI 아래 갈라지는 **하위 명령**이다.  
예: `gostodian run`, `gostodian status`, `docker compose up`에서 `compose`/`up`.  
게이트의 “허용 동사”도 개념적으로 서브커맨드 화이트리스트와 비슷하다.

## 5. 프로세스·systemd·상주 방식

### 유닛 / 데몬

- **데몬**: 백그라운드에서 계속 도는 서비스 프로세스 (`sshd`, `dockerd` 등).
- **유닛(unit)**: systemd가 관리하는 **단위 정의**다.  
  서비스 유닛(`.service`), 타이머(`.timer`), 소켓(`.socket`) 등.  
  “이 프로그램을 언제 어떻게 기동·재시작할지”를 파일로 적어 둔 것.

### transient unit

디스크에 유닛 파일을 永久 저장하지 않고,  
`systemd-run` 등으로 **임시로 만들어 실행하는 유닛**이다.  
재부팅하면 보통 사라진다.  
일회성 작업·짧은 점검 작업을 systemd 감독 아래 돌릴 때 쓴다.

### 재부팅을 넘는 상태

재부팅 후에도 **남아 있어야 하는 상태**다.

- 남는 것: 디스크의 설정 파일, systemd enable된 유닛, 데이터 볼륨, 방화벽 영구 규칙
- 안 남는 것: 메모리上的 프로세스, transient unit, 마운트 안 한 tmpfs 내용

“재부팅을 넘는 상태”를 설계한다는 것은  
부팅만 하면 서비스가 다시 올라오도록 **영구 유닛·볼륨·설정**을 갖춘다는 뜻이다.

### Quadlet

Podman 컨테이너를 **systemd 유닛처럼** 정의·관리하게 해 주는 방식이다.  
`.container` 같은 파일을 두면 systemd가 서비스로 인식해  
부팅 시 기동·재시작 정책을 적용한다.  
“컨테이너를 재부팅 넘는 서비스”로 운영할 때 자주 나온다.

### 폴링

상대에게 이벤트를 기다리기보다,  
내가 **주기적으로 상태를 물어보는** 방식이다.  
예: 5분마다 SSH로 health 확인, 1분마다 메트릭 scrape.  
단순하지만 너무 잦으면 부하가 되고, 너무 뜸하면 감지가 늦다.

### 지수 백오프

실패했을 때 재시도 간격을 **1s → 2s → 4s → 8s…**처럼 지수적으로 늘리는 전략이다.  
상대가 죽었거나 바빠질 때, 재시도 폭풍으로 더 망가뜨리지 않기 위함이다.  
상한을 두고(예: 최대 5분) jitter(무작위 흔들림)를 넣기도 한다.

## 6. 관측·리소스

### 시스템 리소스 사용량 수집 이유

CPU·메모리·디스크·네트워크를 모아 두는 이유는 대략:

1. **점검 전후 비교**: 업데이트/재부팅 후 이상치 확인
2. **용량 계획**: 디스크 가득 참·OOM을 미리 봄
3. **장애 원인**: “그때 CPU가  thrash 했다”를 시계열로 증명
4. **알림**: 임계치 초과 시 Discord 등으로 통지

수집 없는 점검은 “느낌”이고, 수집 있는 점검은 “근거”다.

### 리소스 시계열

같은 지표를 **시간 축으로 이어 저장한 데이터**다.  
“지금 CPU 40%”가 점이라면, “지난 24시간 CPU 곡선”이 시계열이다.  
그래프·이상 탐지·회귀(업데이트 전후)에 필요하다.

### node_exporter

Prometheus 생태계의 **호스트 메트릭 수출기**다.  
CPU, 메모리, 디스크, 네트워크 등을 HTTP 엔드포인트로 노출하면  
Prometheus 등이 긁어간다. “서버 본체” 관측의 기본축.

### cAdvisor

컨테이너의 CPU·메모리·네트워크 등을 수집·노출하는 에이전트다.  
호스트 전체는 `node_exporter`, **컨테이너 단위**는 cAdvisor(또는 유사 스택)로 보는 식으로 역할이 나뉜다.

## 7. 시크릿·레포 보안

### gitleaks

Git 저장소에서 **키·토큰·비밀번호 패턴**을 찾아내는 도구다.  
커밋·CI에서 돌려 “실수로 올린 시크릿”을 막는다.

### 레포가 퍼블릭이므로 gitleaks가 `id_ed25519`, `BEGIN OPENSSH PRIVATE KEY`를 잡는지 확인 — 왜?

공개 레포는 **누구나 클론**할 수 있다.  
개인키가 한 번이라도 커밋되면:

1. 히스토리에 영원히 남을 수 있고
2. 봇이 전 세계 공개 레포를 훑어 키를 수집하며
3. 그 키로 홈랩/서버 SSH가 열릴 수 있다

그래서 gitleaks가  
`id_ed25519` 파일명·`BEGIN OPENSSH PRIVATE KEY` 본문 같은 패턴을  
**실제로 탐지하는지** 미리 확인한다.  
“도구를 넣었다”가 아니라 “우리 레포 기준으로 진짜 막히는지”를 검증하는 단계다.  
시크릿은 레포가 아니라 `secrets/`(gitignore)나 시크릿 스토어에만 둔다.

## 8. 기타 기초 용어

### 파싱

문자열·파일을 **구조화된 데이터로 해석**하는 일이다.  
예: 로그 한 줄을 읽어 시각·레벨·메시지로 분리,  
`SSH_ORIGINAL_COMMAND`를 동사와 인자로 나눔,  
YAML 설정을 구조체로 로드.  
파싱이 틀리면 이후 허용 검사·리댁션·보고서가 전부 틀린다.

## 한 장으로 이어 붙이기 (gostodian 감각)

```
[내 PC / 점검 머신]
    │  VPN (peer와 터널)
    ▼
[OCI: Security List로 퍼블릭 22 차단, VPN 대역만 SSH]
    │  SSH (개인키 0600, known_hosts로 MITM 방지)
    ▼
[서버 sshd]
    │  authorized_keys:
    │  restrict,from="VPN IP",command="gostodian-gate" pub키 gostodian
    ▼
[gostodian-gate (Go 바이너리)]
    │  SSH_ORIGINAL_COMMAND → 허용 동사만 통과
    ▼
[실제 작업: dnf/apt, 서비스, 로그, 메트릭]
    │
    ├─ node_exporter / cAdvisor → 리소스 시계열
    ├─ Podman + Quadlet / systemd unit → 재부팅을 넘는 서비스
    └─ 컨트롤러가 DAG(위상정렬 순서)로 push, 실패 시 지수 백오프
```
